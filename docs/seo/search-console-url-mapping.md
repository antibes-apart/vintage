# Search Console audit — legacy URL mapping and redirect report

Source: Search Console export, 30 Sep – 11 Nov 2026 (`cookandcollect.eu-Performance-on-Search-2026-11-14.xlsx`).
Every product URL in the export was checked against `manifest.json` and the generated pages. All 60
product URLs (22 legacy `item.html?id=`, 38 permanent `/en/collection/`) belong to published items, and
every destination exists in both languages. No product URL is removed or redirected to the home page.

## Rules

| Old URL pattern | Destination | Mechanism |
|---|---|---|
| `/item.html?id=<id>` | `/en/collection/<id>.html` | 301 by the identify-agent Worker route; JS `location.replace` fallback in `js/app.js` until then |
| `/en/item.html?id=<id>` | `/en/collection/<id>.html` | same |
| `/fr/item.html?id=<id>` | `/fr/collection/<id>.html` (French page, never English) | same |
| `item.html?id=<unknown>` | none: the page stays and shows "not found" | Worker passes the request through; JS does not redirect |
| `item.html` without `id` | none | unchanged |
| `/en/index.html` | stays 200; `rel=canonical` → `/` | canonical only (it was a duplicate of `/`) |

- Other query parameters (`utm_*`, …) and the `#hash` are kept; only `id` is removed.
- No loops: destinations are `/collection/` pages, which are never redirected (tested in `tests/seo.test.js`).
- The id → page map is generated by `build.js` as `/legacy-redirects.json`; the Worker reads it, so new items need no
  redirect configuration.
- Sold items keep their pages (marked sold, `SoldOut` in structured data, similar available pieces linked).
